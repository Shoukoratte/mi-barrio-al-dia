# Architecture Decision Records (ADR)

This directory contains the Architecture Decision Records for **Mi barrio al día**.

## Purpose

Document important technical decisions, their context, evaluated alternatives, and consequences.

ADRs help the team understand why architectural choices were made and how they evolve over time.

## Decision Format

Each ADR should include:

- **Title:** Short description of the decision.
- **Status:** Proposed, Accepted, Superseded, or Rejected.
- **Context:** Problem or requirement motivating the decision.
- **Decision:** Selected approach.
- **Alternatives:** Other approaches considered.
- **Consequences:** Benefits, trade-offs, and limitations.

## Guidelines

- Keep each decision in a separate Markdown file.
- Use English for technical documentation.
- Discuss significant architectural decisions before accepting them.
- Prefer creating a new ADR that supersedes an existing one rather than silently rewriting its history.
