# Project Planning

This directory contains planning and progress documentation for **Mi barrio al día**.

## Purpose

Track project objectives, development milestones, requirements, priorities, and progress.

The project follows an iterative, milestone-based workflow inspired by Agile and Kanban practices.

## Project Capacity

| Team Member | Weekly Availability | Main Focus |
|---|---|---|
| Project Lead | 30 hours | Full-stack development, architecture, integration, and code review |
| Frontend Contributor | 6 hours | React, TypeScript, and UI development |
| Junior Contributor | 6 hours | Guided tasks, documentation, and testing |
| **Total** | **42 hours** | |

Availability is an initial estimate and may change.

## Workflow

Development tasks will be tracked using GitHub Issues and GitHub Projects.

Task statuses:

- TODO
- IN PROGRESS
- REVIEW
- DONE

Each task should include a clear objective, an assigned contributor, and acceptance criteria.

## Planned Documents

- `ROADMAP.md` — Development milestones and dependencies.
- `MVP_SCOPE.md` — Approved MVP features and exclusions.
- `PROGRESS.md` — Completed work, blockers, and next actions.

GitHub Issues will serve as the primary operational backlog to avoid duplicating task tracking across multiple documents.

## Change Management

New ideas can be proposed at any time.

Changes affecting the active milestone must be evaluated based on their value, impact, effort, and dependencies.

Significant scope changes must be documented before implementation.
